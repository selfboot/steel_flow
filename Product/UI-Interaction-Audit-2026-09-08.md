# SteelFlow UI 与交互评估

日期：2026-09-08。基线：main / 28f0904，App 1.1.0（9）。

本次检查当前源码与 1.1.0 模拟器回归截图。截图来自 ReleaseGate.xcresult；为避免干扰另一项正在进行的模拟器工作，没有重新操作模拟器，也没有新执行整套 UI 测试。以下区分截图中直接观察到的问题与从代码确认的交互行为；不把推测当成实测卡顿、无障碍失败或真实用户行为。未修改 App 代码。

现有原生分组列表、钢蓝强调色、尺寸示意图和公英制数据表达可继续使用。当前更值得优化的是操作优先级、重复信息、入口深度和任务完成后的反馈。

## 第一轮：优先修正含义不清和容易误操作的交互

### U01 · 高 · 跨币种保存的标题和操作范围不匹配

**证据：** [截图](UI-Review-2026-09-08/currency-save.png) 中的英文标题被截断为“Change project curren…”。快速计算保存到其他币种项目时，复用了“修改项目币种”页面；实际转换的是待保存条目的金额，并没有更改目标项目币种。说明文案仍写所有条目价格/费用，范围也不准确。

**建议：** 区分“更改整个项目币种”和“保存到不同币种项目”两种情境。后者使用短标题“币种不同 / Currency mismatch”，显示“计算 USD → 项目 CNY”，并写明仅处理本次条目。按钮使用“换算并保存”“清空金额并保存”等明确动词；输入汇率时显示 `1 USD = … CNY`，给出本条金额的前后预览。

**验收：** 用户能在同一屏看懂影响对象、币种和金额；英文普通字号标题不截断。保留现有显式确认机制。

**位置：** `CalculatorEditorView.swift:327`、`ProjectSettingsSheet.swift:169`。

### U02 · 高 · 错误提示与不可用的保存按钮缺少直接联系

**证据：** 尺寸输入在计算页上部，错误通常在后部结果区；保存会因计算、计价或历史价格待核对而禁用。报价设置收起时，只展示待核对提示，却没有直接展开并定位价格的按钮。数量输入在结束编辑时还会把超限值钳制到范围内，或恢复原值，未给出原因。

**建议：** 将错误放在对应字段旁，具体写明如“壁厚必须小于外边长的一半”。底部操作区显示无法保存的首个原因并允许定位；“价格待核对”提供“查看并核对”。数量不要无提示地改变用户输入，超限时说明允许范围。保留结果卡位置，在无效输入时显示待补字段，减少卡片插入/移除造成的位置变化。

**验收：** 空尺寸、过厚壁厚、数量 0/超上限、历史价格失配，都能直接定位原因；用户无需上下寻找。

**位置：** `CalculatorEditorView.swift:73, 95, 163, 239, 278`、`DesignSystem.swift:129`。卡片变化是否造成实际滚动跳动仍需交互复测。

### U03 · 高 · 模板名称同时承担“选择”和“立即创建”

**证据：** [截图](UI-Review-2026-09-08/create-template.png) 只有名称输入、清空旧价开关和模板名称列表；源码中点击模板名称直接调用 `create`、保存并关闭页面。新用户可能以为点击是查看内容。保存模板本身也没有命名步骤或成功反馈。

**建议：** 点击模板先选中，显示条目数、主要材料、税率/利润规则、旧价处理状态；底部明确“使用此模板创建”。创建后直接打开新项目。保存模板时允许命名，完成后提示“已保存模板 · 查看”。

**验收：** 点击列表只选择，确认按钮才创建；用户能预先知道模板包含什么，创建后无需返回列表寻找。

**位置：** `CustomersAndTemplates.swift:23`、`ProjectDetailView.swift:123`。

### U04 · 高 · 搜索无结果与没有数据被混为一谈

**证据：** `ProjectsView` 对所有 `visibleProjects.isEmpty` 都显示“没有项目/没有归档项目”，没有区分搜索、模板筛选和真正无数据。筛选与排序藏在“＋”菜单，当前筛选状态不直观。材料页也按原始集合判断空态，搜索无结果时可能只留下分组标题。

**建议：** 拆分“尚无项目”“没有匹配结果”“没有模板”“归档为空”。搜索结果页显示关键词和“清除搜索/筛选”。“＋”保留创建操作，独立的筛选入口显示项目/模板、活跃/归档与排序状态。

**验收：** 搜索不存在的客户时明确显示无匹配结果，而不是引导用户误以为数据丢失并创建新项目。

**位置：** `ProjectsView.swift:20, 30, 88`、`MaterialsView.swift:49, 65`。

### U05 · 高 · 批量修改的默认值和选择方式不够明确

**证据：** 打开页面默认启用“修改损耗”，值为 0；用户选中条目后即具备执行修改的条件。条目选择使用类似功能开关的 Toggle；“选中可见条目”以替换集合的方式实现，会清掉前一次过滤条件下的选择。

**建议：** 默认不启用任何修改项；先选择“改价格/改损耗”，再输入新值。条目用勾选行和规格摘要，固定显示“已选 8 项（当前筛选显示 3 项）”。“全选当前结果”累加选择，并提供独立的“清空全部选择”。确认页具体列出修改字段、前后值及影响数量，保留撤销。

**验收：** 打开后仅选条目不会把损耗意外归零；切换材料筛选不会悄悄丢掉此前选中项。

**位置：** `BulkPricingSheet.swift:30, 68`。

## 第二轮：缩短日常操作路径

### U06 · 高 · 主要操作和结果仍会随长表单滚走

**证据：** 计算页已有顶部重量，但保存仍在整个 Form 最后一组。项目页依次显示条目、七项汇总，再展示报价按钮；[项目截图](UI-Review-2026-09-08/project.png) 只有两行条目，后面的汇总已占据大块空间。条目增多后操作会更深。

**建议：** iPhone 计算页使用底部安全区域中的简洁总重/金额与“保存到项目”主按钮；尺寸输入时仍可查看即时结果。项目页前置“条目数、总重、报价总额”，费用明细可展开，“生成报价”保持易于找到。键盘弹出时收缩操作区，不能覆盖当前输入。

**验收：** 修改长度后无需滚到表单末尾保存；50 条目的项目也能直接进入报价。

**位置：** `CalculatorEditorView.swift:268`、`ProjectDetailView.swift:63, 86`。

### U07 · 高 · 收藏与最近计算位于 13 种截面之后

**证据：** [截图](UI-Review-2026-09-08/favorites.png) 中必须经过整组截面卡片才能看到收藏。收藏操作也在右上角更多菜单里；首页最多直接展开 100 条收藏和 20 条最近记录，数据增多后首页会变长。

**建议：** 有使用记录时按“继续上次草稿 → 常用收藏 3–6 项 → 新建计算/截面 → 最近记录”组织；提供“查看全部”。收藏卡片显示材料、规格、长度/数量和重量，使用正文颜色，星标表达收藏状态；长按菜单只作为快捷补充入口。

**验收：** 老用户进入首页后无需滚动即可复用最近规格；新用户仍能一眼看到如何开始计算。

**位置：** `CalculatorHomeView.swift:38, 50, 137`。

### U08 · 中高 · 完整报价表单缺少渐进展开

**证据：** [截图](UI-Review-2026-09-08/pricing-form.png) 把单价、费用、客户说明、内部备注、供应商、地区、牌号、日期、含税记录放在同一长组。材料选择又位于尺寸和固定 250 pt 示意图之后。客户、公司表单的一些字段只用 placeholder 命名，填入后标签消失。

**建议：** 核心顺序为“材料与规格 → 长度/数量 → 单价”；密度、示意图详情按需展开。报价分为“基础计价”“附加费用”“供应商来源”“客户说明/内部备注”。保留持久字段标签，把币种与计价单位组合表达，如“单价 · CNY/kg”。默认折叠的摘要必须显示已经填写的费用，避免隐藏费用让用户误判。

**验收：** 常见报价只需处理核心字段；展开/收起不会清空输入；填完客户信息后仍能识别字段用途。

**位置：** `CalculatorEditorView.swift:134–232`、`ProfileSection3DPreview.swift:323`、`CustomersAndTemplates.swift:97`。

### U09 · 中高 · 保存、草稿恢复和撤销反馈应统一

**证据：** 计算保存后弹 Alert，“继续添加”只是关闭弹窗，字段保留；收藏、复制条目、保存模板缺少明显成功反馈；进入页面会自动恢复草稿，但没有标明恢复了哪份内容。撤销按钮位于条目之后，长项目可能看不到。

**建议：** 普通成功使用短暂状态条“已加入项目 · 查看 / 撤销”，不打断连续输入；明确提供“同规格再加一项”和“新规格”。恢复草稿显示“已恢复上次输入 · 重新开始”；重新开始应可撤销。只有跨币种、不能恢复的删除等需要决定的操作保留确认弹窗。

**验收：** 用户知道操作成功、保存到了哪里、接下来会保留哪些字段；连续录入不需每次关闭提示框。

**位置：** `CalculatorEditorView.swift:291, 298, 308, 335`、`ProjectDetailView.swift:60, 123, 144`。

### U10 · 中高 · 报价预览、保存版本和分享缺少主次

**证据：** [截图](UI-Review-2026-09-08/quote-export.png) 内，打开 PDF、保存版本、CSV 用途、分享 PDF/CSV 是相邻的同等列表操作；用户先看到数据列表，还要再点一次才能看到实际 PDF。保存版本和分享相互独立，可能分享后才发现没有留历史。导出失败有错误弹窗，但生成状态缺少直接重试入口。

**建议：** 页面优先显示实际 PDF 缩略预览和页数，主操作为“保存版本并分享 PDF”；若允许不保存分享，作为明确次级选项。CSV 则先选用途再分享，按钮写明当前用途，如“导出采购清单 CSV”。生成时显示忙碌状态，失败时留在页面内提供“重试”。不要把打开系统分享面板当成已经发送给客户。

**验收：** 用户能在分享前核对最终样式；主路径会保存对应版本；取消分享不标为已发送。

**位置：** `QuotePreviewView.swift:69–110, 145`。

## 第三轮：提升可读性与一致性

### U11 · 中 · 报价历史详情缺少明确的版本身份

**证据：** [截图](UI-Review-2026-09-08/quote-version.png) 进入某版本后标题依然是“Quote history”，与上一层相同；详情没有展示 v1/v2 的编号。比较区只列当前新增/变化行，删除项没有逐条说明，修改前后的关键值不够直观。

**建议：** 列表与详情统一显示“报价 v2 · 日期”，详情标识“已保存版本”。比较分“新增/修改/删除”，同一行显示旧值→新值；不同币种仅并排显示，不计算虚假的差额。复制修订后直接打开新项目。

**位置：** `QuoteHistoryView.swift:19, 50, 80`。

### U12 · 中 · 材料与价格簿竞争同一长列表，解锁接续也不一致

**证据：** 内置材料、自定义材料与价格记录依次堆叠；常用材料通过长按置顶，但没有清晰的置顶标识。材料页购买后的 `.proPaywall` 没有接续回调，与本轮已完善的项目/备份操作不同：解锁后仍需再点一次创建或复制。

**建议：** 在材料页内区分“材料”“供应商价格”两部分，各自提供搜索和创建入口；常用项显示星标/置顶状态。菜单文案随状态切换为“置顶”或“取消置顶”，避免写成二者并列。材料创建/复制也接续购买前操作。

**位置：** `MaterialsView.swift:34–122`、`ProjectsView.swift:68`。

### U13 · 中 · 可编辑值、计算结果和动作的视觉语义需更稳定

**证据：** 客户表单依赖浅色 placeholder；报价总额在预览中是灰色右列，接近辅助信息；收藏卡片整段文字为链接蓝。不同页面的“编辑”既可能管理条目，也可能编辑项目信息。小屏的币种大标题已有截断实例。

**建议：** 计算结果用主文本色和等宽数字，标签用辅助色，主要动作使用明确的强调样式；详情导航采用短标题。客户编辑页叫“新建客户/编辑客户”；项目的条目整理叫“管理条目”，项目信息编辑叫“项目设置”。保持输入区域可点击性与字段标签，长文字优先换行，不靠整体缩小字体。

**验收：** 中英文都能区分输入、结果和动作；按钮名称准确表达当前操作。灰色问题是视觉层级判断，本次没有测量 WCAG 对比度，因此不作达标/不达标断言。

### U14 · 中 · iPad 与无障碍需要单独验收

**证据：** 现有 iPad 回归截图说明流程可用，但仍主要把手机长表单放到中央 sheet。源码已有部分动态字体适配；此次未重新检查深色模式、横屏、VoiceOver 或实际大字体全流程。

**建议：** iPad 优先采用左侧编辑、右侧实时结果/报价预览；项目可使用列表与详情并列。对最大辅助字号切换单列；屏幕阅读器读出字段名、单位和错误原因；键盘提供上一项/下一项/完成并保持焦点。自定义卡片保留明确按压反馈，复核至少 44×44 pt 的触控区域。

**验收：** iPhone 小屏与 iPad 横屏都能完成录入、保存、报价；深色模式、大字体、VoiceOver 作为独立检查，不用普通 UI 测试通过替代。

## 建议执行顺序与验收任务

1. 先做 U01–U05：修正操作语义、错误定位、模板确认、空态和批量选择默认行为。
2. 再做 U06–U10：前置主要操作与复用入口，缩短报价表单，统一状态反馈及导出路径。
3. 最后做 U11–U14：版本比较、材料导航、视觉层级、iPad 与无障碍。

用以下任务比较改动前后：复用昨天的规格只改长度；修改错误壁厚后保存；跨币种保存；搜索不存在的客户后恢复列表；使用模板创建报价；跨筛选选择条目改价；查看真实 PDF 并保留历史版本。记录点击、滚动、回退次数和误操作，不预先承诺留存或转化提升。

## 设计依据

具体问题依据本项目的代码和截图。通用原则参考 Apple 官方文档：

- [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：主次动作层级、按压反馈和触控区域。
- [Entering data](https://developer.apple.com/design/human-interface-guidelines/entering-data)：减少输入负担、明确字段含义。
- [Writing](https://developer.apple.com/design/human-interface-guidelines/writing)：错误靠近相关字段，并说明如何修正。
- [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts)：避免不必要的打断，对可撤销的常规动作使用更轻的反馈。
